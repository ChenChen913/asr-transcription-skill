## 8. 踩坑清单

> 每条都是「现象 → 原因 → 做法 → 预防」。已泛化，不含具体素材或路径。
>
> **排查前先分归属**：问题出在模型行为、参数组合、脚本 / 解析、还是指标口径？四者对应完全不同的动作——换模型 / 改参数 / 改脚本 / 改指标。分不清就乱试，最费时间。

### 8.1 安装 / 下载

| 现象 | 原因 | 做法 | 预防 |
|---|---|---|---|
| 装一个几 MB 的包几分钟没动静 | 默认源在国外 | 换国内镜像 | 国内机器先试镜像，别死等 |
| 装完 `import` 直接失败 | `--no-deps` 跳过了真正干活的核心包 | 两个包一起装 + import 冒烟测试前置为硬门槛 | 装完先验收，再进主流程 |
| 大文件下到一半断掉 | 单线程、无续传 | 分片 Range 下载、按已有偏移续传、先写分片再合并 | 先探地址可达性，再后台拉 |
| 磁盘比预算多吃几百 MB | 压缩包、解压目录、另一套运行时都留着 | 测完清掉不再需要的下载物 | 预算按「双份」算 |
| 缓存把系统盘吃紧 | 临时目录默认指到系统盘 | 所有缓存变量指到工作区 | 开工前统一设环境变量 |

### 8.2 自己写的工具

| 现象 | 原因 | 做法 | 预防 |
|---|---|---|---|
| 一整批转写全失败，但模型没问题 | 自己写的资源采样辅助函数崩了（Windows 取当前进程返回 `-1`，被 ctypes 当无符号数溢出） | 显式声明 `argtypes`、用固定的伪句柄常量 | **新写的辅助工具先拿 1 条最小样本单跑一次，再上批量** |
| 汇总表整片空白 | 按完整编号精确匹配，实际编号带后缀 | 改前缀 / 分组匹配 | 先打印一条真实数据看清格式 |
| 自动质检报一堆幻觉，一看全是误报 | 规则太粗：「特别长的一段」命中正常长句、「高频两字词」命中常用词 | 剔除这两类规则，只留有证据的关键词命中 | 先人工看几条命中样例再信数字 |
| 结果名对不上、差异度算不出来 | 分组字典用了错的键名 | 统一命名规范，先验证一条 | 写汇总前先看一条原始输出结构 |
| 重跑汇总把旧报告覆盖 | 脚本直接 `open(..., "w")` | 重跑前备份，或锁死口径再写 | 汇总脚本默认写新文件 |

### 8.3 外部程序

| 现象 | 原因 | 做法 | 预防 |
|---|---|---|---|
| 手工试跑成功、批量全失败，报路径乱码 | 原生二进制不能正确处理非 ASCII 路径 | 工作目录切到程序目录、一律相对路径 | 拿一条带中文的路径先试 |
| 字数虚高一倍 | 程序把运行日志和转写正文打在同一行，按「整行过滤」没清掉 | 按日志标记切分、只取前面正文 | 先看一眼原始输出，别假设格式 |
| 换模型后启动报错 | 不同模型的构造参数名不一样（有的叫 `model`，有的叫模型名） | 写之前用 `inspect.signature` 核对 | 换模型先查签名，别照抄 |
| 想做时间轴对齐却没时间戳 | 部分轻量运行时只给纯文本 | 这类方案只当文本参照，对齐仍用主力输出 | 选型时先确认输出结构 |

### 8.4 判断方法（最危险，会得出假的漂亮结论）

| 现象 | 原因 | 做法 | 预防 |
|---|---|---|---|
| 拿画面字幕算准确率，结果明显不对 | 固定标题、装饰字、滚动字幕被混进参考文本 | 加质量门槛（字数比 + 重复率），不合格自动放弃计算 | **尺子不准时宁可不出数字** |
| 原定的「术语命中率」算不了 | 没有术语表 | 该验收项不参与判定，只留定性案例 | 开测前先确认判分依据在手边 |
| 专门为某个毛病设计的开关，测完判不出好坏 | 样本里根本没出现那个毛病 | 如实写「得不出结论」，不要说参数无效 | 想验证什么，样本里就得有什么 |
| 长音频结论站不住 | 样本全是短素材 | 标注「不外推到长音频」 | 先体检样本再定矩阵 |
| 把估算写成实测、把设计写成既成事实 | 多次笔记叠加没归并 | 每个数字标出处；无来源的标「估算 / 推断」 | 写「数据出处」小节，逐条钉到文件或命令 |

### 8.5 Windows / Agent 工具环境

| 现象 | 归类 | 做法 |
|---|---|---|
| 控制台中文乱码（stdout 是 GBK/OEM、控制台按 UTF-8 显示，方向别写反） | Windows | 结果写文件再用 UTF-8 读，别靠控制台看 |
| 后台任务输出为空 | 跨平台 | `print(..., flush=True)` 或直接落盘 |
| 脚本里反引号报错 | Agent 工具环境 | 用数组 `join` 拼文本，别用模板字符串包代码块 |
| 覆盖文件被拒 | Agent 工具环境 | 先读一次再写 |
| 改现有脚本前没留副本 | 流程 | 复制进工作区再改，别动原工具 |
| 批处理与单文件脚本的超时值不同 | 流程 | 按最长素材设，别把两套脚本的数值混写 |
| 一条命令里又有中文路径、又有 JSON 和多层引号，解析直接失败 | 命令 / 工具环境 | 超过几行的逻辑一律落成脚本文件再跑；命令行里不拼 JSON、不嵌套三层引号 |
| 长任务在工具里等全程，结果工具自己先超时 | 工具环境 | 长任务一律后台跑 + 分次看日志；单次等待时间不能设得比工具总时限还长 |
| 首条转写很久没输出，以为挂了 | 工具环境 | 先看日志文件 / 后台任务状态；别拿「没输出」判断失败，脚本里 `print(..., flush=True)` 或直接落盘 |
| 同一条命令换个 shell 版本就报错 | 跨平台 | 不假设 shell 版本一致；先在目标环境跑一条最小样例；统计与 JSON 解析交给 Python，别用 shell 管道拼对象 |
| 结果文件里的中文正常、控制台却乱码 | Windows | 结果统一 UTF-8 写文件再读；Python 加 `-X utf8`，日志 / CSV / JSON 全部 UTF-8 |

### 8.6 三条通用教训

1. **辅助工具先单跑一条再上批量**——否则一个小函数能把整批主任务全带翻。
2. **「我没找到」不等于「它不存在」**——取证先确认项目根目录与一手来源；只搜一个目录就下结论，以及引用过期二手快照，都是同一类错误。
3. **参照物不可信时宁可说测不出来**——假准确率比没有结论更有害，会让接手的人照着错数字排工期、跳过质检。
