## 2. 标准流程（从素材到成稿）

> 路径一律用占位符，开工第一步先确认项目根目录，别把脚本和素材放在不同目录还互相引用相对路径。
>
> **开测前先回答四个问题**（比选模型更优先）：① 这一轮到底要回答什么（选型 / 调参 / 质量 / 资源）？② 判分依据在不在手边（人工稿、官方字幕，还是都没有）？③ 指标口径和资源红线定没定？④ 产物放哪、会不会覆盖旧结果？四个都答完再排执行矩阵。

| 步 | 做什么 | 要点 |
|---|---|---|
| 0 | 确认项目根 + 素材清单 | 先做只读体检：有没有音轨、精确时长、格式、体积；**没有音轨的素材单独告知，不要硬跑** |
| 1 | 建目录 | `<根>/原始素材`（只读）、`<根>/逐字稿`、`<根>/成稿`、`<根>/_tools` |
| 2 | 环境自检 | 跑 §0 的五条命令；已就绪就跳过安装与下载 |
| 2.5 | 先探字幕轨 | 有**文本**字幕轨就抽出来，第 3–6 步整段跳过（见 §2.0） |
| 3 | 抽音频 | `ffmpeg -y -i "<素材>" -vn -ac 1 -ar 16000 -c:a pcm_s16le "<输出>/<编号>.wav"`；**只抽一次，多方案共用同一份输入**，保证可比 |
| 4 | 主力转写 | 参数见 §3；输出 `.json`（结构化）+ `.md`（带时间戳可读版） |
| 5 | 补充方案转写（可选） | 见 §4；用于快速预览或第二意见 |
| 6 | 对齐差异 | 两份文本归一化后算差异，**人工只看分歧处和长间隙区间**，省时间 |
| 7 | 质检 | 见 §5；四个指标只当粗筛，必须补首末段检查 |
| 8 | 精编 | 建术语表统一替换专名；补标点、数字规整；原始稿保留不覆盖 |
| 9 | 留痕 | 记录模型版本、参数、耗时、素材时长、复核命令、许可证；便于下次复现 |

> ⚠️ **默认转写链路只处理音频，不读画面像素。** 唯一的例外是 §2.0 的字幕轨抽取——它取的是容器里的**文本**字幕流，不是图像。第 3 步用 FFmpeg 把视频里的声音抽成 WAV 之后，画面就不再参与任何识别计算。文中提到的「抽帧」是 §5 的另一条**可选质检旁路**，只在没有文字稿、又想做量化对照时才启用，详见 §5.5。

### 2.0 先探字幕轨：能省掉一整轮转写

一条内嵌**文本**字幕轨是零成本的真值：不用模型、不用 GPU、不会听错人名，几秒钟就得到一份带时间点的稿。所以它排在抽音频之前——有就抽，没有才转。同目录下同名的 `.srt/.ass/.ssa/.vtt` 优先级更高。

```bash
# 只列不抽：先看这个文件到底有什么轨
python scripts/extract_subs.py --input "<素材>" --out-dir "<输出>" --list

# 抽出来（外挂字幕优先，其次内嵌文本轨）
python scripts/extract_subs.py --input "<素材>" --out-dir "<输出>"

# 多语言文件里指定第几条 / 只认某语言
python scripts/extract_subs.py --input "<素材>" --out-dir "<输出>" --stream 1
python scripts/extract_subs.py --input "<素材>" --out-dir "<输出>" --lang zh
```

三条边界，越界拿到的是假结果：

- **只认文本轨。** PGS / VobSub / DVB 抽出来是一串图片，脚本会明确拒绝并提示需要 OCR；硬字幕（烧进画面）根本不在这条链路里。
- **它是字幕，不是逐字稿。** 字幕作者会省略语气词、合并长句、自己断句，用词偏书面。产物 MD 头部写明来源与这一条，别直接拿它当「准确率基准」。
- **不改时间轴。** 源字幕重叠就照着重叠写，只在 MD 与 `stats.overlaps` 里报数——改时间戳等于改证据。

退出码：`0` 至少抽出一份 | `2` 参数或输入不可用 | `3` 一份都没抽出来（无轨、只有图形轨、或抽取失败）。拿到 3 就照常往下走。

产物带 `"engine": "subtitle-track"`，`qc_check.py` 据此**跳过字/段密度两条警告**（字幕本来就不按逐字稿的密度写），重叠、长间隙、片尾话术照旧检查。

### 2.1 没有字幕轨：读画面里的硬字幕

字幕烧进像素时，`extract_subs.py` 无能为力（图形轨也会被它拒绝）。这时用 `ocr_subs.py`，它把画面下半幅逐帧喂给 PP-OCR。

```bash
# 先探：这个视频到底有没有会变的字幕带？（16 帧，几秒）
python scripts/ocr_subs.py --input "<素材>" --list

# 有就逐帧读
python scripts/ocr_subs.py --input "<素材>" --out-dir "<输出>" --fps 1.0

# 长视频降采样，耗时与 fps 成正比
python scripts/ocr_subs.py --input "<素材>" --out-dir "<输出>" --fps 0.5
```

字幕带不是猜的，是**从 OCR 自己的框里读出来的**：

1. 先按字号分位数（本片自身分布的 60%）只留较大的字——屏幕录制里界面文字比字幕小得多，这一步把它们滤掉；
2. 以每个框的中心开一个 ±5% 高度的窗口评分，得分 = 覆盖帧比例 × 文本变化种数 × 字号权重；
3. 取分最高且最靠下的窗口，收紧到字幕尺寸的框。

留白是**两段口径**：给检测器裁剪时上下各留 5% 画面高度（`crop`），判定"什么算字幕行"时只看收紧后的核心带（`core`）。只留 1.2% 时裁剪线会压在字形描边上，PP-OCR 会把一整行读成碎片——实测 `Topk要用最小的值获得` 连续 6 秒被读成 `doL`，留到 5% 才稳定（置信度 0.91）。反过来，留白越大，压在字幕上方的界面元素越容易混进来，所以 `core` 必须单独存在：同一素材放宽留白后字数从 1736 涨到 2537，多出来的全是叠字。

**不要退回"把相邻的框聚成一簇"**：那是单链聚类，屏幕上每几像素就有一个框，整块下半屏会被连成一条 49% 高的"带"，所有屏幕录制素材都会被拒。这条教训写在 `ROADMAP.md` v0.7。

#### 找对位置之后，还要找对那一行

字幕带只回答"哪一片区域有字"，不回答"哪一行在说话"。真实素材里另外两行很常见，都会把稿子写坏：

- **双语字幕**：译文印在口播下面，两行同步变化，图里没有任何线索能指出哪行是说的。按 `--language`（默认 `zh`）保留主语言。不丢的代价是量出来的：同一段 111 秒素材从 692 字涨到 2816 字，而且互校时英文把相似度压到几乎每对都判"不一致"。
- **固定文案**：要点条、章节点、流程图常压在字幕下方，字号一样、也在带内，唯一区别是**换得慢**。按"一次停留连续多少帧几乎不变"剔除——实测口播 2 帧、要点条 9–17 帧。

  三个细节都是踩出来的：**单位是停留而不是位置**（同一位置上章节点停 17 秒、中间闪过一句台词，整槽删会连台词一起删掉，实测 `发票要寄到上海办公室` 就是这样丢过一次）；**判据是"几乎不变"而不是"一字不变"**（OCR 对同一张卡每帧有一两个字的抖动，按相等判会把 9 帧的卡切成 2 帧，看起来和对话一模一样）；**相似度门槛要 0.9**（这里放宽会把两句相邻台词粘成一段长停留，然后被当成固定文案删掉）。

  两个保险：别的行必须快 2.5 倍以上才动手；不低于 5 秒绝对下限，整片都慢换（歌词、长引文）时一行不动。**逐帧都在变的图表仍然分不开**，它的节奏和对话一样快。

判定用的是**连续帧**，不是跨全片抽样：均匀抽样会把"停了多久"这个信息抽没，要点条和字幕的变化种数会变得一样。

剔除的槽位与丢掉的译文行数都写进产物头部和 `params`（`furniture` / `translations_dropped`），不会悄悄少字。同一行里的叠字（弹幕、覆盖在字幕上的角标）仍然分不开——纵向切分只能分开不同的行。

五条边界：

- **只读下半幅**（默认 `--region 0.50,0.995`）。字幕在画面上方、竖排、花字、被人物挡住的，都读不到；另起一行的固定文案能按节奏剔除，压在同一行里的叠字不能。
- **小字号不准**。一行只有十几像素时（640×360 这类），同一句在两种留白下会读出不同结果，错字率明显高于竖屏 720p/1080p。
- **比转写慢**：约 0.38 s/帧（含抽帧与写盘），1 fps 下 3 分钟视频约 1 分钟。默认不跑，按需跑。
- **需要 OCR 运行时**（`rapidocr_onnxruntime` + `onnxruntime`，13 MB 模型随 wheel）。没装时脚本报错退出，其余脚本不受影响。
- **它是另一份证据，不是标准答案**。OCR 会认错形近字（`懵逼`→`憎逼`），也可能把水印、标题读进来。产物 MD 头部写明这一点，`engine=ocr` 与字/段密度警告的关系见 §2.1 末尾。

退出码：`0` 至少读出一份 | `2` 参数、环境或 OCR 运行时不可用 | `3` 没有一个文件找到可读的字幕带。拿到 3 就回落到转写。

`qc_check.py` 对 `engine=ocr` 与 `engine=subtitle-track` 用同一把尺子：**只跳过字/段密度两条**，重叠、长间隙、片尾话术、提示语回音照旧。

### 2.2 听看互校：只把分歧交给人

两份稿子都有之后，别人工通读比对，跑：

```bash
python scripts/merge_sources.py --heard "<听.json>" --seen "<看.json>" --out "<输出>/01.merge.md"
```

它做的事：按"看到的那条字幕的中点落在哪段语音里"对齐（不是按重叠，重叠会把一句字幕算进两段，导致同一句被引用两次）；逐段算相似度，分成 一致 / 接近 / 不一致 / 只有语音 / 只有字幕；MD 只列后四类里的前两类，按可疑程度排序。

三个刻意的设计：

- **不产出合并稿。** 两份都不可靠，混起来只会更不可靠，而且无法再验证。要给客户的是"哪几处需要确认"，不是第三份来路不明的稿子。
- **数字不一致直接升为"不一致"**，哪怕整句相似度 0.95。`K=50` 与 `K=60` 差一个字，字符相似度和字形都看不出来，只能靠 token 比对。
- **先测时间偏移。** 短视频的字幕常比语音晚 1–2 秒。不校正的话每一段都会被判成不一致；校正值写进报告，但**两边原始时间一律不改**。

怎么用报告：`不一致` 段回到音频听一遍再定；`接近` 段多半是同音字或断句差异；`只有语音` 是字幕没覆盖的时段（正常，但若正好是关键结论，值得单独听）。**谁对谁错脚本不判**，这是刻意的。

### 2.3 素材来源的通用提醒

- **先确认文件里真的有音轨**：`ffprobe -show_streams` 看不到 audio stream 就不要硬跑。部分视频站把音视频分开存放，某些编码版本（如 HEVC 的 mp4）只有视频流，音频是独立的一条流，需要单独取；能拿到 h264 + aac 的封装文件最省事。
- **下载站点资源要带正常的请求头**（来源页 Referer + 浏览器 UA），否则可能拿到 403 或验证页。
- **遇到登录墙不要硬绕**：改分页参数常会破坏签名、返回验证页。让用户自己把素材下载好、只做转写，反而更快。
- 上述站点行为属于**一次性观察**，站点改版后要重新确认，别写进流程当永久规则。

### 2.4 批处理工程要点

- **先试脚本，别手写循环**：`scripts/batch_transcribe.py` 已覆盖多目录取文件、跳过已完成、失败隔离、每文件独立 JSON。用法见 `10-commands.md`；它只做串行四件事，没有队列/并发。
- **一次任务 = 一组成套产物**：`<key>.json` + `<key>.md`。判「已完成」必须两份都完整（JSON 可解析且含 `segments`/`duration`，MD 存在且非空）；只看 JSON 会把「写完 JSON 就被 Ctrl-C 打断」的文件误判为完成，那份给人看的 `.md` 就永远不会生成。对应的写入顺序是**先落 MD、再落 JSON**（各自 `.tmp` + 原子改名），保证「有 JSON ⇒ 有 MD」。
- **强制重跑要把两份一起挪走**：只把旧 JSON 改成 `.prev`、把旧 MD 留在原位，会在失败后留下一个看起来像本轮结果的旧逐字稿——而 `.md` 恰恰是人真正会读的那份。两份要么一起进 `.prev`，要么一起留。
- 手写循环时（例如要接自定义前处理），**状态就是输出文件本身**：判断「`<key>.json` 与 `<key>.md` 都在且能解析」即可续跑，别再维护一份状态文件——两份状态一定会漂移。
- 循环里每个文件独立 `try/except`，失败只记日志并跳过，不中断整批。
- `ffmpeg` 设足超时（长文件 900 s 起），防止异常文件卡死。
- **手写循环也只吃 PCM WAV**：`transcribe.py` 用标准库 `wave` 读时长，收到 m4a/mp3 会以 `cannot read WAV` 退出 2。文件名匹配（`--pattern`、`glob`）跟「能不能解码」是两件事，别在收文件那一步就假定格式没问题。用 `batch_transcribe.py` 则不用自己写这一步：它会先把非 WAV 解到 `_batch/audio/` 再转写（见 `10-commands.md`）。
- 真要维护状态文件（多机、跨轮补跑）时，别和主流程共用一个：后补批次用独立文件，避免口径混算。
- 汇总脚本如果会**覆盖已有报告**，重跑前先备份，或给脚本加集数白名单锁死口径。
- **每轮新建独立输出目录**，别覆盖上一轮；固定一份样本清单（样本 ID ↔ 源文件 ↔ 时长 ↔ 统一 WAV），产物用 `<配置>_<样本ID>` 命名，全程只用 ID。
- **原始输出只写一次、不手改**；任何修正放到下游脚本里做，保证结果可追溯。
