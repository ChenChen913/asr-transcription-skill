## 0. 一页速查

### 推荐组合

| 角色 | 方案 | 用在哪 |
|---|---|---|
| **主力** | faster-whisper + `large-v3-turbo`，GPU / float16 | 所有正式稿，尤其含英文缩写、产品名、人名的中英混读内容 |
| **补充** | SenseVoice q8 GGUF 独立运行时（纯 CPU、无需 Python / torch） | 批量快速预览、当「真正异源」的第二意见、只核分歧处 |
| 对照 | `large-v3` 完整版，GPU | 疑难片段复核；**不要当主力** |
| 应急 | turbo / CPU / int8 | 显卡不可用时的回退路径 |

### 开工前五条自检

1. `nvidia-smi` 能看到显卡 → 有卡就别用 CPU。
2. `python -c "import faster_whisper, ctranslate2; print(faster_whisper.__version__, ctranslate2.get_cuda_device_count())"` → 能出版本号且设备数 ≥1。
3. 模型目录存在，且含 `config.json` / `preprocessor_config.json` / `tokenizer.json` / `vocabulary.json` / `model.bin` 五个文件。
4. CUDA 的两个算子库（cublas / cudnn 的 DLL）在 Python 的 site-packages 下找得到，**多数情况下在用户级目录，不在解释器目录**。
5. `ffmpeg -version`、`ffprobe -version` 都在 PATH。

> 前三条任一不过，先修环境，别急着转写；已装好的环境不要重复安装、重复下载。

### 五件绝对不要做的事

- **不要关掉 `initial_prompt`**：关掉后标点密度几乎归零（掉到 0–0.1/百字），整篇糊成一片。
- **不要拿四个数字指标当「合格」**：它们查不出凭空冒出来的内容，也查不出开头被整段替换。
- **不要把 turbo 和 large-v3 当两个独立引擎做交叉验证**：turbo 是 large-v3 的解码器剪枝版（32→4 层），共享同一个编码器和训练数据，错误高度相关。
- **不要照抄排行榜或别人的倍速**：题材不同结论会反转，见 §1.8。
- **不要在可用内存吃紧的机器上装 torch 系大模型**：内存往往比显存更早成为瓶颈。

### 转完必做三查（比任何指标都重要）

1. **查开头 30 秒**：有没有把提示语原文念进正文、有没有片头话术、真实开场是不是被整段吃掉。
2. **查结尾 30 秒**：有没有凭空冒出「谢谢大家 / 感谢观看 / 请不吝点赞…」，最后一段的结束时间是不是**超过了音频总时长**。超过就是多出来的幻觉段，不是「尾部空为负 = 合格」。
3. **查中间长间隙**：任意相邻两段时间间隔 **> 8 秒** 直接标红，回听该区间，或拿异源方案的输出对照。

> 这三项是硬检查，不是参考值。不同配置、不同素材上分别中过招，属于系统性风险，不是偶发。

## 1. 方案选型

### 1.1 主力：faster-whisper（SYSTRAN）+ Whisper large-v3-turbo（OpenAI），GPU

选它的理由：底层是 OpenNMT 的 CTranslate2 推理引擎，CPU 可用、不依赖 torch、GPU 支持好、能直接吃普通目录里的模型权重（不走缓存）、**默认输出段级起止时间戳**便于对齐。

> ⚠️ 别把「段时间戳」写成「词级时间戳」：`word_timestamps` 默认 `False`，输出里每段只有起止时间和文本；要词级需显式打开，会更慢、更占资源（见 §3）。写能力描述前先看一条真实 JSON 的字段。

主要短板：**专有名词靠软引导，没有原生热词**；中文长音频上不一定优于国产模型；长静音或试麦段可能凭空生成内容。

### 1.2 补充：SenseVoice（QwenAudio）+ FunASR GGUF 运行时（CPU）

模型是 QwenAudio（原 FunAudioLLM）的 SenseVoiceSmall，独立运行时与 q8 GGUF 量化由 modelscope/FunASR 项目发布（基于 ggml-org/llama.cpp）。一个可执行文件 + 一个模型文件 + 一个静音切分模型，**不需要 Python、不需要 torch、纯 CPU、零显存**。速度最快、内存最省、标点最密，适合：

- 大批量先快速过一遍，看个大概；
- 与主力各转一遍，**只人工核对两边不一样的地方**；
- 显卡被别的事占着时继续干活。
- 主力输出出现长时间空隙时，用它对照该区间是否另有内容（**漏段探测**）。它偶尔能补出另一边漏掉的片段，但**通常不完整、文本也可能较乱，只能当线索**，不能当补回来的正文。

必须说清的限制：

- **中英混读的专名明显弱于主力**（英文缩写、产品名容易听成音近汉字）。重要稿子不能只用它。
- **输出没有任何可用时间信息**（运行时只给一个覆盖全长的整段，看似有起止时间其实是占位），只能当纯文本参照，不能做时间轴对齐或字幕，**也不能用它判断「尾段是否越界」**。
- 权重许可是 **FunASR Model License**（代码仓库是 MIT，两者要分开看），商用前核对署名等义务。

### 1.3 对照：large-v3 完整版

同音词、人名上偶尔比 turbo 稳，但**速度约为主力的 1/3、内存与显存占用约为 2–3 倍**，容易顶到资源红线。它还会**引入主力没有的新毛病**（开头把提示语念进正文、结尾生成片尾话术）。只留作疑难片段复核，别当日常主力；**定向复核时开头和结尾都要看**，别只盯着有疑问的那一段。

### 1.4 应急：turbo / CPU

不占显存是唯一优点，速度约为主力的 1/7。只在显卡不可用或做小规模验证时用。

### 1.5 需要改造才能用 / 不推荐

| 方案 | 问题 |
|---|---|
| SenseVoice int8 ONNX（k2-fsa/sherpa-onnx 导出，Python 包） | 与 1.2 是同一套权重的不同装法，但明显吞字、更慢、更占内存；被独立运行时全面压制 |
| Paraformer 中文 ONNX（modelscope/FunASR 模型，sherpa-onnx 导出） | 输出**一个标点都没有**，不能直接出可读稿，必须外接标点 / 数字规整模型 |
| 云 ASR API | 要联网、要账号、长音频切分麻烦；离线约束下不进选型，只可作真值对照 |
| 同源 whisper.cpp 权重（ggml-org/whisper.cpp） | 与主力同一套模型，不构成独立第二意见 |

### 1.6 明确排除

需要 torch / Transformers / vLLM 的整套方案（FunASR Python 版、QwenLM 的 Qwen3-ASR、m-bain 的 WhisperX、说话人分离）、7B 级以上的端到端语音模型。理由：**可用运行内存不足时，光是把依赖装完就吃不消**，且 8 GB 显存装不下大模型。等第一轮证明「异源确实有收益」、并换到内存更空闲的机器再单开一轮。

### 1.7 参考量级对比

> 下表只用于判断**相对关系**（谁快、谁省、谁标点多），数字随机器和素材变化，不要当性能指标。

| 方案 | 速度 | 运行内存 | 显存 | 标点密度 | 中英混读专名 | 能单独出正式稿 |
|---|---|---|---|---|---|---|
| 主力 turbo / GPU | 约 19× | 约 +1.2–1.6 GB | 约 +1.9–2.1 GB | 中等 | **最稳** | ✅ |
| large-v3 / GPU | 约 6× | **约 +3.0–3.1 GB** | **约 +3.8–3.9 GB** | 中等 | 同音词略好 | ✅ 能，但代价大（不作主力） |
| turbo / CPU | 约 2.6–2.9× | 约 +1.4–1.5 GB | 0 | 中上 | 同主力 | ✅ 慢 |
| **SenseVoice q8 GGUF / CPU** | **约 27–28×** | **约 +0.36–0.37 GB** | 0 | **最高** | **弱** | ⚠️ 预览 / 对照 / 漏段线索 |
| SenseVoice int8 ONNX / CPU | 约 8.7× | 约 +1.3 GB | 0 | 中上 | 弱、且吞字 | ❌ |
| Paraformer int8 ONNX / CPU | 约 11.5× | 约 +0.9 GB | 0 | **0** | 弱 | ❌ 需后处理 |

> 「×」指实时倍率：1 分钟的音频用 60÷倍率 秒转完。内存 / 显存取**批次最大峰值增量**（不是典型值），样本规模与后台负载不同会有约 30% 波动，别当硬指标。
>
> **数据出处**：以上倍率与资源量级来自本机多轮实测，素材为 1–4 分钟量级的中文短口播（含中英混读、术语密集），单机单卡；不是跨机型基准，长音频 / 会议 / 朗读不能外推。机型与环境快照见仓库 README。

### 1.8 三条选型原则

1. **同源不等于独立**：要真正独立的第二意见，必须换不同架构、不同训练数据的引擎。同系列两版一起听错，不能推断「这个词确实难」。
2. **题材决定排名**：短、竖屏、术语密集、中英混读的口播上，Whisper 系往往比中文模型稳；长会议、长朗读上中文模型可能更好。网上榜单多测后者，**别外推到自己的素材**。
3. **内存比显存更要命**：可用运行内存 < 5 GB 时，先排除一切要装大依赖的方案；所有方案串行跑、一次只加载一个模型、测完立即释放。
